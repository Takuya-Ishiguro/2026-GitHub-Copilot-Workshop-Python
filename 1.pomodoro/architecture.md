# ポモドーロタイマーWebアプリ アーキテクチャ案

## 1. 概要

本アプリは、Flask（Python）＋HTML/CSS/JavaScriptで構築するポモドーロタイマーWebアプリです。添付のUIモックを参考に、シンプルかつ拡張性・テスト容易性を重視した設計とします。

---

## 2. ディレクトリ構成（例）

```
1.pomodoro/
├── app.py                # Flaskアプリ本体（ファクトリパターン推奨）
├── logic.py              # タイマー・進捗管理等のビジネスロジック
├── templates/
│   └── index.html        # メイン画面のHTMLテンプレート
├── static/
│   ├── css/
│   │   └── style.css     # カスタムCSS
│   └── js/
│       └── timer.js      # タイマーのロジック（JavaScript）
├── data/
│   └── progress.json     # 今日の進捗などを保存（必要に応じて）
└── tests/
    ├── test_logic.py     # Pythonロジックのテスト
    └── test_app.py       # Flaskアプリのテスト
```

---

## 3. 各層の役割

### Flask（バックエンド）
- ルーティング（例：`/` でメイン画面表示）
- 今日の進捗データの保存・取得（ファイルやDB、セッションなど）
- 必要に応じてAPIエンドポイント（例：進捗記録の保存/取得）
- アプリ生成はファクトリ関数（`create_app()`）で行い、テスト容易性を高める

### ビジネスロジック（logic.py）
- タイマーや進捗管理などのロジックをFlaskルートやJSから分離
- 単体テスト可能な関数・クラスとして実装

### HTML（テンプレート）
- UIの骨組み
- Jinja2で動的に進捗データを埋め込む

### CSS
- モック画像のような美しいデザインを再現

### JavaScript
- タイマーのカウントダウン・進捗の更新
- 「開始」「リセット」ボタンの動作
- 必要に応じてバックエンドと非同期通信（fetch/AJAX）
- タイマーや進捗計算などのロジック部分は関数化し、Jestなどで単体テスト可能な構造に

---

## 4. 進捗データの管理
- シンプルな場合はセッションやローカルストレージで管理
- 複数端末や永続化が必要ならサーバー側でファイルやDBに保存
- 本番用データとテスト用データを切り替えられる設計

---

## 5. テスト容易性への配慮
- Flaskアプリとロジックの分離
- テストディレクトリ（`tests/`）の設置
- APIやJSロジックの関数化
- テスト用データの切り替え
- 入力値検証やエラーハンドリングも関数化してテストしやすく

---

## 6. 拡張性
- ユーザー認証を追加すれば個人ごとの進捗管理も可能
- DB（SQLite等）を使えば履歴管理も容易

---

## 7. まとめ
- シンプルな構成で開発・テスト・拡張がしやすいアーキテクチャ
- UI/UXは添付モックを参考に実装
- 必要に応じてAPIやロジックを追加・分離し、保守性を高める
